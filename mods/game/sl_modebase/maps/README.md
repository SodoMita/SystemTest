# Handmade maps (.mts schematics)

Match maps come in three types (see `sl_map.type` and `/sl_map`):

| type          | what it is                                                     |
|---------------|----------------------------------------------------------------|
| `procedural`  | seeded generated arena, rebuilt identically from its seed      |
| `test`        | the deterministic test arena (`test_harness.lua`)              |
| `schematic`   | handmade arena loaded from a schematic — this directory        |

This directory holds the handmade maps. Two examples ship with the game:

* `neon_crossfire/` — a `map.mts` in the binary WorldEdit format
  (generated by `tools/gen_example_map_mts.py`).
* `mini_test/` — the same idea in plain-Lua schematic form (`map.lua`),
  for readability.

All handmade maps get the same reset contract as generated ones: when a
match ends the schematic is re-placed over its whole volume (nodes
created or dug during the match are replaced with the initial state),
mobs are purged, and the map's mob population respawns at the next
match start.

## Creating a map with WorldEdit (the MTCTF workflow)

1. Build the arena in-world (any game that has your nodes; this game's
   structural set is `ground:square_neon`, `ground:square_neon_opaque`).
2. Select it with the WorldEdit wand and save it:
   `//schem save mymap`
3. Copy `<world>/schems/mymap.mts` into
   `mods/game/sl_modebase/maps/mymap/map.mts`
   (the game scans `<world>/schems/` and `<world>/maps/<name>/` too, so
   you can also leave it in place).
4. Write `mods/game/sl_modebase/maps/mymap/map.conf` (see below).

No WorldEdit needed? Build or generate an arena in-game, then run
`/sl_map save mymap` (creative mode) — it exports the current map
volume to `map.mts` and writes a starter `map.conf` you can edit.

## map.conf reference

Coordinates are **schematic-relative**: the min corner of the saved
schematic is `0,0,0`, exactly how WorldEdit reports positions.

```ini
# metadata
name = Neon Crossfire
author = SodoMita

# placement rotation of the schematic: 0, 90, 180 or 270
rotation = 0

# schematic size X,Y,Z. Optional when the engine can read the size from
# the .mts header; required for map.lua tables is nothing (size is in
# the table). When in doubt, write it.
size = 49,7,49

# Gameplay anchors (schematic-relative).
beacon_a.pos = 6,2,24     # beacon A node; players spawn on top
beacon_b.pos = 42,2,24
altar.pos = 24,2,24       # ghost altar node
mm.pos = 24,2,41          # Monster Master spawn pad
lobby.pos = 24,1,4        # lobby player STAND position (not a node)
ghost.pos = 24,12,24      # cloud cage anchor

# Initial mob population, respawned at every match start.
# variant: any game_mode.MONSTER_TYPES id (stalker, scout, brute,
# dredger, wraith, containment)
mobs.1 = 12,2,12,stalker
mobs.2 = 36,2,12,scout
```

Rules of thumb:

* The beacons, altar and MM pad **nodes** are placed by the game at the
  anchor positions — you build the structures around them, not the
  nodes themselves.
* Anchors that end up floating in the air get an automatic 3x3 pad
  underneath; still, placing them on your own structures looks better.
* Missing keys fall back to sensible defaults on top of the schematic
  (beacons at 20 %/80 % width, altar centered, MM at the far end).
* Without `mobs.N` entries the game scatters `sl_map.mobs` monsters
  (default 6) over the top of the placed schematic.

## Selecting maps

```
/sl_map                 # current map + what the next match uses
/sl_map list            # installed handmade maps
/sl_map schematic NAME  # use NAME for the next matches (admin)
/sl_map schematic       # random handmade map each match (admin)
/sl_map build           # build the selected map right now (admin)
```

or persistently via `settingtypes.txt`:

```
sl_map.type = schematic
sl_map.schematic = neon_crossfire
```

## Procedural layout overrides

The procedural generator's anchors can be moved with four settings (each an
`"x,z"` position on the arena floor; Y is derived from the map origin):

```
sl_map.cage_pos      = 5,5      # cloud cage column (default: arena centre)
sl_map.beacon_a_pos  = -30,2    # beacon A bastion (default: midfield line)
sl_map.beacon_b_pos  = 30,2     # beacon B bastion (default: midfield line)
sl_map.mm_base_pos   = 0,40     # Monster Master redoubt (default: +Z edge)
```

Unset entries keep the stock arrangement. The resolved layout is carried on
the map descriptor, so the match-end rebuild (reset) reproduces the
overridden anchors exactly even if the settings are edited mid-match;
`/sl_map save` exports whatever is currently standing, overrides included.
If both beacon positions are set to the same spot, beacon B falls back to
its default with a warning. The same anchors can be fixed for handmade maps
via `map.conf` (`beacon_a.pos` / `beacon_b.pos` / `mm.pos` / `ghost.pos`).
